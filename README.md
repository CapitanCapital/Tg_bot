# Tg_bot — новостной дайджест для Telegram

Tg_bot собирает новости из публичных источников, готовит краткую подборку на русском языке и публикует её в Telegram по расписанию. Темы дайджеста — технологии, искусственный интеллект, бизнес и финансы.

## Решаемая задача

Поток новостей требует постоянного чтения множества каналов и сайтов. Одно событие часто повторяется в нескольких источниках, а важные сообщения перемешаны с рекламой и мелкими обновлениями.

Проект автоматизирует сбор, отбор и подготовку ежедневного выпуска: сохраняет исходные материалы, объединяет сообщения об одном событии, учитывает историю публикаций и формирует компактный пост со ссылками. Редакционные критерии вынесены в отдельный файл и могут изменяться независимо от кода.

## Основная функция

Основная функция — полный цикл подготовки и доставки новостного дайджеста:

1. Сбор материалов из включённых публичных Telegram-страниц и сайтов.
2. Сохранение текста, ссылки, даты и идентификатора источника в SQLite.
3. Проверка свежести материалов и исключение повторов с учётом опубликованных выпусков.
4. Отбор новостей, написание выжимки и проверка результата языковой моделью.
5. Проверка структуры, ссылок, подтверждающих фрагментов и длины сообщения в коде.
6. Сохранение готового выпуска в дневную очередь отправки — outbox.
7. Публикация в согласованный Telegram-канал в заданное время.

Сборщик и генератор черновика сами по себе ничего не отправляют. Публикация реализована отдельным обработчиком.

## Формат результата

Итог — один Telegram-пост с HTML-разметкой, обычно из 5–7 пунктов, без общего вступления и заключения. Каждый пункт содержит короткий заголовок, 1–2 предложения с сутью события, значимые цифры и ссылку на оригинал.

Предпочтительный состав выпуска: 3–4 новости технологий, 1–2 новости бизнеса и финансов, до одного исследования или прогноза. Значимость важнее квот: при недостатке материалов выпуск короче, а при отсутствии подходящих новостей публикация пропускается.

Локально сохраняются:

| Артефакт | Назначение |
| --- | --- |
| `data/materials.sqlite3` | Собранные материалы |
| Отчёты сбора JSON и JSONL | Результаты получения материалов и диагностика источников |
| `data/draft-*/` | Кандидаты, результаты этапов модели, итоговый JSON и представления Markdown/HTML |
| `data/outbox-YYYY-MM-DD.json` | Подготовленный выпуск либо отметка о пропуске |
| `data/deliveries.sqlite3` | Учёт попыток отправки и идентификаторов сообщений |
| `data/published.json` | Постоянная история опубликованных новостей |

## Используемый стек технологий

| Технология | Роль в проекте |
| --- | --- |
| Python 3 | Сбор, обработка, проверки и управление публикацией |
| Стандартная библиотека Python | HTTP через `urllib`, HTML через `html.parser`, JSON, процессы, параллельный сбор и работа со временем |
| SQLite | Хранение материалов и защита от повторных отправок |
| Codex CLI | Основной обработчик этапов отбора, написания и проверки; используется сохранённая авторизация ChatGPT |
| OpenAI Responses API | Альтернативный обработчик при явном выборе провайдера |
| OpenRouter API | Альтернативный обработчик, ограниченный в коде моделями `:free` и нулевой ценой маршрутизации |
| Telegram Bot API | Отправка готового поста с HTML-разметкой |
| Linux, systemd и shell | Серверные службы, расписание и установка таймеров |
| `unittest` | Автоматические тесты без реальной отправки сообщений |

Python-код использует стандартную библиотеку: отдельные пакеты из PyPI для него не требуются. Режим публикации рассчитан на Linux/Unix и использует `fcntl`. Модели выполняются во внешних сервисах; локальная модель и Docker в текущей реализации не используются.

## Структура проекта

```text
src/
  collect.py          # сбор материалов
  draft.py            # отбор, написание, проверка и рендеринг
  codex_api.py        # адаптер Codex CLI
  openrouter_api.py   # адаптер OpenRouter
  schedule.py         # подготовка outbox и отправка в Telegram
config/
  sources.yaml        # источники; содержимое в формате JSON
  editorial-rules.md  # редакционные правила
deploy/
  server.example.json # пример локальной конфигурации сервера
  *.service           # службы systemd
  *.timer             # расписание systemd
tests/                # тесты
.env.example          # пустой шаблон настроек
```

## Подготовка к запуску

Создайте виртуальное окружение и локальные конфигурации из шаблонов:

```sh
python3 -m venv .venv
cp .env.example .env
cp deploy/server.example.json deploy/server.json
```

Заполните `.env` нужными значениями:

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота для публикации |
| `TELEGRAM_CHAT_ID` | Идентификатор согласованного канала |
| `OPENAI_API_KEY` | Нужен только при выборе OpenAI |
| `OPENROUTER_API_KEY` | Нужен только при выборе OpenRouter |

Для основного режима нужен установленный и авторизованный Codex CLI. Адаптер ожидает исполняемый файл по пути `~/.local/bin/codex` и авторизацию в `~/.codex`. Автоматического переключения с Codex на API-провайдеров нет.

В `deploy/server.json` заполните параметры своего окружения. Поле `publish_at` задаёт время окна публикации; расписание systemd нужно согласовать с ним отдельно.

**Текущая версия привязана к согласованному каналу:** `TARGET` в `src/schedule.py` должен совпадать с `TELEGRAM_CHAT_ID`. Одного изменения `.env` для другого канала недостаточно. Перед использованием в своём канале обновите назначение в коде и редакционных правилах и предоставьте боту права публикации.

## Запуск

Сбор материалов:

```sh
.venv/bin/python src/collect.py
```

Код завершения `2` означает частичную недоступность источников: подробности находятся в отчёте сбора.

Создание и проверка черновика без отправки:

```sh
.venv/bin/python src/draft.py --provider codex
```

Альтернативы при наличии соответствующих ключей:

```sh
.venv/bin/python src/draft.py --provider openai
.venv/bin/python src/draft.py --provider openrouter
```

Подготовка дневной очереди запускает сбор и генерацию:

```sh
.venv/bin/python src/schedule.py prepare
```

Следующая команда **отправляет сообщение в Telegram**. Она допускается только в течение 15 минут после времени `publish_at` по Москве:

```sh
.venv/bin/python src/schedule.py publish
```

## Расписание и надёжность

Включённые в репозиторий таймеры рассчитаны на ежедневную подготовку в 08:30 и публикацию в 09:00 по `Europe/Moscow`. Службы используют пользователя `digest` и каталог `/home/digest/tg-news-digest`.

После подготовки сервера, настройки окружения и авторизации Codex таймеры устанавливаются от root:

```sh
sh deploy/install-timers.sh
```

Скрипт `deploy/prepare-server.sh` предназначен для первичной подготовки ОС: устанавливает системные пакеты, создаёт пользователя и окружение, при определённых условиях добавляет swap. Перед запуском проверьте его под своё окружение.

Блокировка не допускает одновременную работу обработчиков. SQLite фиксирует попытку отправки до обращения к Telegram. После неопределённого результата автоматического повтора нет: нужно проверить канал вручную. Такая политика уменьшает риск дублей, но не гарантирует доставку.

Если outbox отсутствует, повреждён или устарел, обработчик отправляет сообщение `ошибка в проверке и сборе поста`. Корректный пустой выпуск с отметкой `skip` не отправляется. При недоступности Telegram сообщение об ошибке тоже может не доставиться.

При обновлении сохраняйте `data/`, `.env`, локальную конфигурацию сервера и авторизацию Codex.

## Безопасность

Ключи хранятся в локальном `.env`, который исключён через `.gitignore`. В репозитории публикуются только пустые или обезличенные шаблоны. Также исключены данные, логи, конфигурация сервера, каталоги авторизации и распространённые файлы приватных ключей.

Не добавляйте секреты в исходники, отчёты или коммиты. Если действующий ключ уже попал в публичный доступ, отзовите его и создайте новый: удаление файла не удаляет значение из истории Git.

## Тесты и ограничения

```sh
.venv/bin/python -m unittest discover -s tests
```

Тесты проверяют сбор и преобразование материалов, адаптеры моделей, ограничения формата и сценарии доставки без реальной отправки в Telegram.

Доступность публичных страниц и сервисов может меняться. Набор источников задаётся в `config/sources.yaml`; несмотря на расширение, файл читается как JSON. Окно кандидатов в коде составляет сутки для Telegram и семь дней для остальных источников; результаты сбора должны быть не старше шести часов.

Проверка модели сопоставляет текст с собранными материалами и не является независимым подтверждением фактов. Расходы и доступность внешних моделей зависят от выбранного провайдера и аккаунта.
